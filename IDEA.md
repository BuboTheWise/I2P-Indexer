I2P is an encrypted network similar to TOR except the intent is not to obscure exit traffic, it is to become it's own secure private network. The problem is the way it works fundamentally is that you have to have prior knowledge of a sites key to direct traffic to it. There are publishers of known sites in the form of text files you can import into an "address book" of a proxy. The intent of this project is to be given a proxy address, and slowly crawl the sites in the address book to create a database of the site content and organize it by type and disposition. The resulting database should be able to be used to search for what sites are out there based on these groupings and narrow down to more specific analysis. I suggest a layered approach where we first try to get a rough grouping of all known sites and then slowly narrow in on them with more detail as opposed to trying to fully analyze each site as we see it.  The lightest touch possible over time. I2P is inherently and even intentionally slow, so just an initial categorization holds a lot of value for later analysis. 

The code for this project should obviously be configurable for proxies but for this effort we have one to use. The proxy for actual traffic is "http://localhost:4444" and the Address Book URL is "http://localhost:7657/susidns/export?book=router".  I think that initially sqllite is ideal for this project due to ease of use and portability. I do want a lightweight UI for searching this database as well. A web page is the simplest in my opinion for similar reasons but I'm open to any better ideas there.
